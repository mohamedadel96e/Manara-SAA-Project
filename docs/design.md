# Design notes

## Requirements translated into decisions

| Requirement | Design decision |
| --- | --- |
| Connect a data center to several VPCs | One Transit Gateway provides the regional hub instead of a mesh of VPC peerings and VPNs. |
| Keep Dev, Staging, and Prod address spaces distinct | Four non-overlapping `/16` VPCs are created: three environments plus Shared Services. |
| Use dynamic routing | The Site-to-Site VPN uses IKEv2 and BGP. Static VPN routes are disabled. |
| Avoid one-tunnel dependency | AWS creates two VPN tunnels; the customer router should configure and monitor both. |
| Resolve names in both directions | Inbound Resolver endpoints answer data-center queries for the AWS private zone. Outbound endpoints forward the corporate suffix to on-premises DNS. |
| Inspect hybrid and east-west traffic | A Transit Gateway-attached Network Firewall sits between ingress and destination route tables. |
| Support multiple AWS accounts | An optional AWS RAM share publishes the Transit Gateway to organization, OU, or account principals. |
| Audit network changes | CloudTrail, AWS Config, VPC Flow Logs, VPN logs, and Network Firewall logs are enabled. |

## CIDR plan

| Network | CIDR | Purpose |
| --- | --- | --- |
| Dev VPC | `10.10.0.0/16` | Development workloads |
| Staging VPC | `10.20.0.0/16` | Pre-production workloads |
| Prod VPC | `10.30.0.0/16` | Production workloads |
| Shared Services VPC | `10.100.0.0/16` | Route 53 Resolver endpoints and shared services |
| On premises | `172.16.0.0/16` | Corporate network advertised through BGP |

Each VPC has two `/24` private subnets in separate Availability Zones. None receives a public IP automatically. The defaults are examples; replace them only with non-overlapping ranges.

## Transit Gateway route-table model

Default association and propagation are disabled. This prevents an attachment from becoming reachable merely because it exists.

### Inspection enabled

| TGW route table | Associated attachments | Destination | Next hop |
| --- | --- | --- | --- |
| Ingress | Dev, Staging, Prod, Shared, VPN | Each connected VPC CIDR | Network Firewall attachment |
| Ingress | Dev, Staging, Prod, Shared, VPN | On-premises CIDR | Network Firewall attachment |
| Post-inspection | Network Firewall | Each VPC CIDR | Matching VPC attachment |
| Post-inspection | Network Firewall | BGP-learned corporate prefixes | VPN attachment through propagation |

This two-table model forces packets through the stateful firewall in both directions. The Network Firewall policy allows hybrid ICMP, DNS, and HTTPS and drops other traffic. Extend the allowlist for real application ports.

### Inspection disabled

Setting `enable_network_firewall = false` removes the firewall and routes the VPC prefixes directly. The VPN propagates its BGP routes into the ingress table. This is useful for a short, lower-cost lab, but it no longer demonstrates centralized inspection.

## Hybrid DNS flow

### On premises to AWS

1. A corporate DNS server receives a query for `service.aws.example.internal`.
2. Its conditional forwarder sends the query to both Route 53 Resolver inbound endpoint IPs.
3. Traffic crosses the VPN and Transit Gateway inspection path.
4. Route 53 Resolver answers from the private hosted zone.

### AWS to on premises

1. A workload asks the VPC resolver for `host.corp.example.internal`.
2. The forwarding rule sends the query through the outbound Resolver endpoints.
3. The shared-services VPC route sends it through Transit Gateway, Network Firewall, and the VPN.
4. The corporate DNS server returns the answer over the same inspected path.

The Terraform output `resolver_inbound_ips` contains the targets for the on-premises conditional forwarder.

## Security boundaries

- Customer gateway pre-shared keys are generated by AWS and stored in Secrets Manager.
- The repository contains no AWS credentials, VPN keys, or Terraform state.
- Resolver security-group rules allow DNS only from the connected CIDRs.
- Network Firewall follows an allowlist for the lab instead of allowing every east-west port.
- Transit Gateway default association and propagation are disabled.
- The audit bucket blocks public access, enforces TLS, encrypts objects, and applies retention.
- VPC Flow Logs record accepted and rejected traffic for every VPC.

## Known constraints

- Terraform provisions the AWS side. A real customer gateway must be configured with the generated tunnel parameters, BGP neighbors, and Secrets Manager PSKs.
- A documentation address (`203.0.113.10`) is the default customer-gateway IP and must be replaced before apply.
- Network Firewall, Transit Gateway attachments, Site-to-Site VPN, Resolver endpoints, logs, and data processing incur charges.
- Direct Connect is described but not provisioned because it requires a physical or hosted connection and provider coordination.
- The sample firewall policy permits only ICMP, DNS, and HTTPS. Real applications need an approved port matrix.
- Production deployments should use remote Terraform state with locking and encryption rather than local state.
